# Multi-seed evaluation

Generated by `scripts/multi_seed_eval.py --seeds 1 2 3 4 5 --mandate-count 25 --event-count 70`, run against the real Groq API (no mocking), 5 independent seeds, each in its own isolated SQLite database (25 mandates / 70 events per seed). Deliberately skips the execute stage — see the script's module docstring for why that doesn't affect any number reported here.

## Why this exists

A single pipeline run gives a point estimate. It doesn't tell you whether that number would look materially different on a re-roll of the dice. This run answers that for the three headline numbers reported from Day 8 onward.

## What this means, plainly

- **Classifier accuracy is a genuinely stable claim.** Post-P3-fix (Day 10), quoting "~99.7% classifier accuracy" is well-supported — it barely moved across 5 independent re-rolls (0.98–1.00).
- **The simulated recovered revenue number is NOT stable and should never be quoted as a bare point estimate.** A ~4.6x spread between the luckiest and unluckiest seed means "INR 8,047" (Day 8's single-run number) or any other single figure is not representative on its own — only a range or an explicit "±" is defensible. This tracks `retry_plan_count`, which itself swings 16–32 on essentially the same generative process — at this batch size, how many events happen to land in retry-eligible categories (vs. hard-fail or structurally-vetoed ones) is itself high-variance, and revenue is a downstream multiplier of that.
- **`retry_exhausted_nudge` never fired across 5 seeds.** Not a bug — it requires the rarer escalate reasons (low classifier confidence, or a negative-EV plan, or "all vetoed" for a non-structural reason like imminent expiry), none of which are common in a normal random batch at this scale. Worth knowing before citing its 0/225 Day-8 count as if it were a meaningfully-measured near-zero rate — it may just not have had a chance to fire yet, not be structurally rare.

## Caveat on this analysis itself

n=5 seeds is enough to demonstrate the *qualitative* claim (accuracy stable, revenue not) but not enough to put a tight confidence interval on the variance numbers themselves — the stdevs above have their own sampling error. Good enough for "is this claim safe to make in a panel interview," not a substitute for a proper power analysis if more rigor is ever needed here.
